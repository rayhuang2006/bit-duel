# 给 GPT / Claude 的參賽指令模板（可直接複製給兩個模型）

你參加的是 **Bit Duel v0.2 的 game-001 三輪試驗賽**（主辦人已將原定十二輪縮為三輪；目前 Round 1、2 已完成）。你不是在撰寫任何網頁、伺服器、利用漏洞或安全競賽程式。你只要設計一份可以由 `bitduel.asm` 編譯成最多 **128 bytes** 的 Bytecode 策略。

不同輪次使用不同的秘密初始狀態（8 trials），同輪交換攻守使用相同狀態。請先閱讀完整 `RULES.md`、`bitduel/vm.py`、`examples/local.asm`，以及目前公開的 `results/<game>/leaderboard.json` 和**上一輪**公開回饋。絕對不要假裝知道對手未揭露的程式或私有筆記。

## 必須做的事情

1. 建立自己的 `strategy.asm`，使一份程式同時支持 role=0 進攻與 role=1 防守。注意 `r2` 為低 32-bit 觀測、`r3` 為時間步、`r1` 為持續記憶。程式必須在 **512 條 VM 指令**內停止，`r0` 的 popcount 不超過 4。
2. 用 `python -m bitduel.cli assemble strategy.asm --out strategy.bin` 編譯，確保大小 <=128 bytes；用你能使用的本機測試方法檢查不會違規。
3. 請提交你自己的、可以公開查核的數學研究報告 `research_note.md`，包括：觀察、推測、根據、提出的數學式、相對前一輪的改動、以及下一輪前可以核對的預測。可以坦言未知或失敗，不要捏造以前的研究成果。這不是要求你提供內部思維鏈。
4. 交付 `strategy.bin` 與 `research_note.md` 給提交者，或使用 `python -m bitduel.cli submit ...` 產生密封留言，在指定 GitHub Issue 發布。
5. **不得查閱任何尚未結束的對手程式與備註**，不得修改 `rules/VM/referee` 或繞過執行限制。你可以使用外部數學工具或 Python 幫你構思策略，但實際控制器必須是 <=128 bytes bytecode。

## 你可以做的數學探索

- 在 `F_2` 上研究 `L=I+R+R^3` 和 `H=I+R`，尋找不變量、周期、分解及控制方法。
- 利用只觀測低 32 bits 的限制，設計猜測隱藏狀態與對手風格的有限狀態機。
- 觀察對手的公開分數、固定 sparse probes，提出可被推翻的假說；測試反制策略而不是只寫亂數。
- 隨機化不是禁忌，但如果選擇使用，請在研究筆記說明混合策略的數學理由與其相對於確定性規則的好處。

最重要的不是當輪勝負，而是第三輪結束後能公開比較兩份程式演化史，清楚指出自己觀察到什麼結構、哪些錯誤推測被修正、對手的什麼方法值得學習。

**賽程提醒**：請完成 Round 3 後停止。裁判會自動揭露所有三輪原始程式、研究筆記和初始種子；請在揭露後才分析對手程式，不要自行提交 Round 4。
